# Правила базы (читает агент)

Где правда, слои, git, запреты. Шаги — в `skills/kb-*/SKILL.md` в корне репозитория, сюда их не копировать.

Основная ветка: `main`.
Скиллы: `kb-search` и `kb-maintain` сейчас; `kb-snapshot` и `kb-index` потом. Доп. скиллы — шаблон: источник, MCP/клон и папку wiki человек дописывает **до** первого вызова. Когда включаете — в этой строке скилл тоже «сейчас»; для снимка папку раздела — в дерево ниже.

## 1. Где правда

| Где | Роль |
|-----|------|
| Этот git (`knowledge-base/wiki/`, `raw/`, `indexes/`) | Правда команды после merge |
| Живой трекер | Правда статусов «как в системе»; в БЗ — снимок wiki (`kb-snapshot`), не raw |
| Спеки и порталы | Правда у источника; в БЗ — указатель (`kb-index`), без копии тела |
| Confluence / внутренний портал | Витрина **после** merge. Не место правок |

`raw/` и wiki разошлись — верить **wiki**. В wiki нет — «в базе этого нет», из raw не добирать.

## 2. Слои и потоки

| Слой | Путь | Суть |
|------|------|------|
| Raw | `knowledge-base/raw/` | Заметки, из которых делают страницы |
| Wiki | `knowledge-base/wiki/` | Страницы с YAML-шапкой; один концепт = один файл |
| Index | `knowledge-base/indexes/` | Карточки-указатели **без** тела |
| Schema | `knowledge-base/AGENTS.md` | Этот файл |

| Что просят | Куда | Скилл |
|------------|------|--------|
| Вопрос | ответ со ссылкой | `kb-search` |
| Файл в raw/ | wiki | `kb-maintain` (ingest) |
| Правка страницы | wiki | `kb-maintain` (update) |
| Живой реестр | `wiki/<раздел>/` | `kb-snapshot` |
| Спеки / портал | `indexes/` | `kb-index` |

## 3. Git

- **Поиск:** `git fetch origin main`, читать `origin/main`. Не `checkout main`, если человек на ветке ingest.
- **Даты:** `DD-MM-YYYY`.
- **Запись:** ветка `kb/<DD-MM-YYYY>/<суть-en>` → один коммит после «ок» → PR → **merge делает человек**.
- Ingest: в том же коммите wiki + `log.md` + файл из `raw/`.
- Агент **не** push в `main`, не force-push, не merge PR.

### Конфликты

Нельзя: force-push, `git reset --hard`, оставлять маркеры конфликта, выдумывать текст.

1. `git status` — какие файлы.
2. `log.md` — оставить обе записи, новые сверху.
3. `index.md` — ссылки без дублей.
4. Два несовместимых факта — стоп, показать человеку, не коммитить.
5. В файлах не должно остаться `<<<<<<<`.

## 4. Дерево

```
knowledge-base/
├── AGENTS.md
├── index.md
├── log.md
├── raw/
├── indexes/
│   ├── sources.md
│   └── entries/
└── wiki/
    ├── teams/
    ├── processes/
    └── glossary/
```

Новый раздел в `wiki/` — человек создаёт папку руками и дописывает её в это дерево. Папки сами не выдумывать.

## 5. Шапка страницы

Обязателен `type`. Лучше заполнить и `title`, `description`, `owner`, `status`, `sources`, `updated`.

До «ок» в дереве можно `status: review`; в коммит уходит `current`. Страницы `draft` / `review` в ответах помечать: ещё не согласованы.

```markdown
---
type: Команда
title: Дельта
description: Одно предложение
owner: Дельта
status: current
tags: [команда]
sources: [raw/example-note.md]
updated: 20-09-2026
---
```

## 6. Нельзя

- Писать в БЗ из `kb-search`.
- Отвечать из `raw/` и `log.md`.
- Копировать тело спеки или портала, если у документа уже есть дом.
- Индексировать feature-ветку источника.
- Править витрину как правду.
- Merge / push в основную ветку.
- Несколько коммитов на один ingest, update, снимок или индекс.
