# С нуля

Это шаги с доклада: взять образец → **свой** репозиторий → два скилла → вопрос и заметка.

Дальше идите по этой инструкции. Сегодня `AGENTS.md` и файлы `SKILL.md` в папке `skills/` открывать не нужно — их читает агент сам. К дереву в `AGENTS.md` вернётесь на неделе, если заведёте новый раздел.

Нужны git, git-хост (GitHub, GitLab или Bitbucket) и редактор с агентом **внутри этой папки** — например Cursor, не чат в браузере. Другой такой редактор тоже подойдёт: в его справке найдите каталог skills (папка, внутри которой лежит `SKILL.md`). Без такого каталога шаг 2 не закрыть — сначала редактор, не скиллы.

В стартер доклада не пушить и не открывать PR. Merge только в репозиторий вашей команды.

## 1. Свой репозиторий

Не Fork и не PR в стартер. Fork оставляет связь с чужим репо. Нужна **своя** копия: история с чистого листа, merge только у вас.

**GitHub.** На странице стартера справа вверху: **Использовать этот шаблон**. В английском интерфейсе кнопка называется **Use this template**. Дальше — **Создать новый репозиторий**. [Как это выглядит](https://docs.github.com/ru/repositories/creating-and-managing-repositories/creating-a-repository-from-a-template). Затем:

```bash
git clone <URL-вашего-репо> my-team-wiki
cd my-team-wiki
```

**GitLab или Bitbucket.** Создайте **пустой** репозиторий на хосте и клонируйте его. В этот клон скопируйте из стартера три вещи: `knowledge-base/`, `AGENTS.md`, `skills/`. Первый commit и push — сюда, не в стартер. Если git-хост для вас новый — этот шаг можно пройти с коллегой; дальше инструкция снова ваша.

Например в Cursor: **File → Open Folder** на `my-team-wiki`. Не открывайте чат «из облака» без git.

## 2. Два скилла

Копируете только `kb-search` и `kb-maintain` из папки `skills/` **вашего** репозитория в редактор. `kb-snapshot` и `kb-index` сегодня не копировать.

Например в Cursor, из папки `my-team-wiki`:

```bash
mkdir -p .cursor/skills
cp -R skills/kb-search .cursor/skills/
cp -R skills/kb-maintain .cursor/skills/
```

Для всех проектов те же две папки можно положить в `~/.cursor/skills/`.

Откройте **новый Agent-чат из папки `my-team-wiki`**. Не Ask, не браузерный ChatGPT. Первое сообщение — со слэша (`/kb-search` или `/kb-maintain`), иначе агент «не видит» скилл.

## 3. Попробуйте скилл поиска

Чат — Agent, из папки **вашего** репозитория. Слэш — первая строка. Задайте два вопроса.

**1.** Факт из базы:

```
/kb-search

Кто отвечает за команду Дельта и где это описано?
```

Должна прийти ссылка на `knowledge-base/wiki/teams/delta.md`. Откройте её и посмотрите шапку в начале файла: `type`, `owner`, `status` — это ручки страницы, не просто текст. Эту страницу агент оформил из `knowledge-base/raw/` — для ответа правда wiki, не raw. Если агент выдумал или дал ответ без ссылки — напишите: «ответь только по wiki, со ссылкой».

**2.** Чего в базе нет:

```
/kb-search

Сколько живут муравьи?
```

Честный ответ: в базе этого нет. Не выдуманная справка про муравьёв.

## 4. Попробуйте скилл внесения информации

Это учебный круг, не «положить знание с нуля». Страница Дельты уже есть в wiki: вы правите состав в заметке, агент обновляет уже существующие страницы.

Ветку создаёте вы, не агент. Имя: `kb/<ДД-ММ-ГГГГ>/<суть-латиницей>`. Дата — сегодняшняя (день-месяц-год), не копируйте пример как есть.

```bash
git checkout main
git pull
git checkout -b kb/21-11-2026/team-roles
```

Откройте `knowledge-base/raw/example-note.md` и поправьте состав команды или зоны. Затем в чат:

```
/kb-maintain

Внеси в базу то, что лежит в knowledge-base/raw/example-note.md
```

Сначала придёт план — wiki ещё не трогают. Напишите **ок** или **правки**. После «ок» агент делает один коммит и PR **в ваш репозиторий**. Если коммит и push есть, а PR не открылся — создайте его сами в UI хоста: ветка `kb/…` → `main` (Compare & pull request / Merge request / Create pull request). Ссылка должна вести в ваш репозиторий, не в стартер. **Merge в UI хоста нажимаете вы.** Агенту merge не отдавать.

## На неделе

Шаги выше — это контур: агент уже отвечает со ссылкой, а правки идут через вас. Дальше база должна стать **вашей**, а не про учебную Дельту.

За неделю соберите небольшое ядро — 5–10 страниц, на которые команда реально ходит: кто в каких командах и за что отвечает, роли, один-два живых процесса, рабочие термины. Кладите черновик в `raw/` и вызывайте скилл `/kb-maintain` по инструкции выше.

Разделы в `wiki/` (команды, процессы, глоссарий и т.д.) заводите вы — папки создаёте **руками**. Если карту wiki меняете (новый раздел, переименование, убрали папку) — откройте в `AGENTS.md` только блок «Дерево»: допишите или поправьте ту же папку. Остальное в файле не трогайте. Агент читает дерево как схему и сам разделы не придумает. Страницы внутри по-прежнему оформляет агент через `/kb-maintain`.

И ещё привычка: вопросы к базе — через `/kb-search`, не «просто чатом». Так вы сразу видите, чего не хватает на странице, а не красивую выдумку.

## Потом, не сегодня

Два дополнительных скилла — когда ядро уже живёт и появляется то, чего руками через `raw/` не вывезешь. Ставить папки в редактор можно сразу. **Вызывать** — только когда свой источник уже прописан. Скопировать скилл ≠ получить наш контур с Jira и порталом: в шаблоне нет вашего фильтра, MCP и папки wiki.

**Снимок реестра** (`kb-snapshot`) — для живого трекера: Jira, другой реестр, CSV. Статусы меняются каждый день, «запомнить моделью» их нельзя. Скилл кладёт срез **сразу в `wiki/`**, минуя `raw/`. Правда статусов в трекере; в git — картинка на момент merge.

Перед первым «сними реестр» допишите:

1. MCP трекера **только чтение** — или положите CSV/JSON вне `raw/`.
2. Папку в `wiki/` руками (часто `wiki/registry/`) и ту же папку в дерево `AGENTS.md`.
3. В шапке `AGENTS.md` у `kb-snapshot` вместо «потом» — «сейчас».
4. В чате (и лучше в `skills/kb-snapshot/SKILL.md`): система, фильтр вроде JQL, поле-ключ, каталог wiki.

**Указатели** (`kb-index`) — для спек в другом репозитории и страниц портала: дом у документа уже есть, копировать тело в wiki нельзя. Скилл пишет карточки в **`knowledge-base/indexes/`**: ссылка и смысл. Деталь агент читает в источнике через MCP или локальный клон.

Перед первым «обнови индекс» допишите:

1. Строку в `knowledge-base/indexes/sources.md`: `id`, что за источник, ветка или корень, маска путей, где клон.
2. Клон на диске (агент сам не клонирует) **или** MCP источника — для git часто [GitHub MCP](https://github.com/github/github-mcp-server); для портала — его MCP, если есть. Без этого агент видит только карточку.
3. В шапке `AGENTS.md` у `kb-index` — «сейчас».

Пока нет трекера и чужих доков — эти скиллы не трогайте. Merge снова вы.

## Если сломалось

Не чините всё сразу — пройдите вопросы по порядку.

**Сделали Fork.** История привязана к стартеру. Начните шаг 1 заново: шаблон → свой репозиторий. Из форка не пушить и не открывать PR в стартер.

**Чат не там.** Скилл вызывается из папки вашего репозитория, не из стартера и не из браузера. Первая строка — слэш (`/kb-search` или `/kb-maintain`). Если агент «не видит» скилл — закройте чат и откройте новый Agent из этой папки.

**Скилл не тот.** Для вопроса — поиск, для заметки в `raw/` — ведение. Snapshot и index работают, только если вы уже скопировали их в skills и поправили шапку в `AGENTS.md`.

**Ветка не та.** Вносить знание можно только с ветки `kb/<ДД-ММ-ГГГГ>/…`, не с `main`. Поиск ветку не создаёт. Если агент пушит в `main` или в стартер — остановите. Merge нажимаете вы.

**PR не открылся.** Коммит на ветке `kb/…` — это нормально. Создайте PR сами в UI хоста: эта ветка → `main`. Нет кнопки — проверьте, что push ушёл в ваш репозиторий, не в стартер, и что вы не на `main`. Агенту merge не отдавать.

**Wiki не та.** Сначала смотрите `knowledge-base/wiki/` и дерево в `AGENTS.md`. Страницы может ещё не быть — тогда «в базе этого нет», а не выдумка: положите черновик в `raw/` и внесите через ведение. Раздела может не быть — папку создаёте руками. Если папка уже есть, а агент её не видит — дерево в `AGENTS.md` устарело, поправьте его. Для ответа правда wiki, не `raw/`.

**Съехал git.** При конфликте после pull не делайте force-push. Как развести файлы — в [AGENTS.md](AGENTS.md), раздел «Конфликты».
