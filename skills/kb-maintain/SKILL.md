# Ведение базы знаний

Правила — `knowledge-base/AGENTS.md`. Только ingest из raw и правка страницы.

Порядок: diff → план в чат → правки в дереве → «ок» → `status: current` → **один** коммит → PR. До «ок» не коммитить и не пушить. Amend нельзя.

Основная ветка — `main`.

## Кто создаёт ветку

- **Ingest** — человек. Агент не pull и не создаёт ветку. Нужна ветка `kb/<DD-MM-YYYY>/…`, не `main`. Иначе стоп: ветку не создавать, wiki не писать.
- **Update** — агент: `git pull origin main` → `git checkout -b kb/<DD-MM-YYYY>/update-<слаг>`. Конфликт на этом pull — раздел «Конфликты» ниже, ветку не создавать поверх сломанного дерева.

После PR: ссылка, список файлов, просьба смержить. Merge — человек. Витрину агент не публикует.

Повторный `git pull origin main` — только если push отклонён: `main` ушёл вперёд. Новый коммит и amend при этом нельзя. Дальше — «Конфликты».

## Конфликты

Та же процедура, что в `knowledge-base/AGENTS.md`, раздел «Конфликты».

Нельзя: force-push, `git reset --hard`, оставлять маркеры конфликта, выдумывать текст.

1. `git status` — какие файлы.
2. `log.md` — оставить обе записи, новые сверху.
3. `index.md` — ссылки без дублей.
4. Два несовместимых факта (разный владелец, статус, противоречащие определения) — стоп, показать оба варианта человеку, не коммитить.
5. В файлах не должно остаться `<<<<<<<`. Дальше продолжить ту же операцию: ingest или update.

## Операция 1. Ingest

**Предусловие:** ветка `kb/<DD-MM-YYYY>/…`, не `main`. Иначе стоп: ветку не создавать, wiki не писать. Файл в `knowledge-base/raw/` или в одной подпапке (`raw/ivanova/note.md`). Глубже не искать.

1. `git status` и `git diff` по указанному raw. Читать **содержание**, не имя файла.
2. План в чат. Wiki ещё не трогать. Неясно куда — спросить, страницы не создавать.
3. Создать или обновить страницы (не плодить дубли).
4. Шапка: `type` обязателен; `status: review`; `sources` — путь как в шаблоне (`raw/example-note.md` или `raw/<папка>/note.md`); `updated` = сегодня `DD-MM-YYYY`.
5. Обновить `wiki/<раздел>/index.md` только в разделе, который уже есть. Корневой `knowledge-base/index.md` — только разделы; листья туда не писать. Новую папку в `wiki/` не создавать и в дерево `knowledge-base/AGENTS.md` не дописывать: папку и строку в дереве заводит человек. Нет нужной папки — стоп, спросить.
6. Запись в `knowledge-base/log.md`: `## [DD-MM-YYYY] ingest | <описание>`.
7. Не коммитить. Список в чат: wiki **и** путь raw. «Согласуй: ок / правки».
8. «правки» — править дерево, снова список. Коммита нет.
9. После «ок»: на затронутых wiki-страницах (не index/log) `status: current`. Проверить, что не осталось `review`. Затем **один** коммит: wiki + `log.md` + файл raw. `git push` → создать PR в `main` штатным способом команды (gh / GitLab / кнопка). Push отклонён — «Конфликты», не второй коммит. Ссылка в чат.

## Операция 2. Update

Ветку создаёт агент (см. выше).

1. Открыть страницу, внести правки, обновить `updated` и связи.
2. `log.md`: `## [DD-MM-YYYY] update | <страница> — <что>`.
3. Список → «ок / правки». Коммита нет.
4. После «ок»: `current`, один коммит, push, PR, ссылка. Push отклонён — «Конфликты», не второй коммит. Merge — человек.

## Шаблон страницы

```markdown
---
type: <Тип>
title: <Имя>
description: <Одно предложение>
owner: <Команда>
status: review
tags: [тег]
sources: [raw/<путь>.md]
updated: <DD-MM-YYYY>
---

# Описание
...

# Источники
[1] ...
```

## Не этот скилл

`kb-search`, `kb-snapshot`, `kb-index`.
